# 이음선 실기기 검증표

이 문서는 재현 계획이며 실제 통신망에서 통과했다는 기록은 아닙니다. 테스트 전 기기·Android 버전·통신사·자동 전환 설정을 기록하세요. 본인 기기와 본인이 관리하거나 사용을 허락받은 테스트 네트워크에서만 진행합니다. 실기기 로그를 공유할 때 Wi‑Fi 이름, 주소, 가입자 정보는 가립니다.

| 재현 조건 | 기대 결과 | 관찰 포인트 |
| --- | --- | --- |
| 강하고 인터넷이 열리는 Wi‑Fi + 데이터 켜짐 | 기본 연결 Wi‑Fi 표시, 불필요한 전환 요청 없음 | 연결됨과 인터넷 확인 상태가 따로 보이는지 |
| 신호를 한 번 잠깐 약화 | 즉시 약한 연결로 굳어지지 않음 | 지연 기준 이전에 회복하면 경고가 고정되지 않는지 |
| 약한 Wi‑Fi를 유지하고 모바일 데이터 켜 둠 | 약화 경고 및 모바일 경로 관측 여부 표시 | 모바일 준비가 기본 연결 변경으로 표시되지 않는지 |
| 로그인해야 하는 테스트 Wi‑Fi | 로그인 필요 상태와 적절한 설정 안내 | 열린 Wi‑Fi라는 이유만으로 로그인 필요라고 판정하지 않는지 |
| Wi‑Fi가 끊기고 셀룰러 경로가 생김 | 기본 경로 변경이 앱 상태·기록에 반영 | 기록은 상태 관측일 뿐 세션 보존을 뜻하지 않는지 |
| 데이터 꺼짐·SIM 없음·비행기 모드 | 대기 요청 실패 또는 관측 불가를 정확히 표시 | 앱이 데이터를 멋대로 켜거나 성공을 표시하지 않는지 |
| 모바일 준비 요청 뒤 앱 이탈 또는 요청 종료 | 임시 요청 종료 | 재진입 시 이전 대기 완료 상태가 잘못 남지 않는지 |
| VPN 또는 제조사 전용 연결 최적화 사용 | Android가 앱에 보여 주는 상태 기준 동작 | VPN 우회, 트래픽 가로채기, 다른 앱 강제 변경이 없는지 |

같은 조건으로 세 차례 이상 반복해 Wi‑Fi 약화 인식까지 걸린 시간, Android 기본 경로 변경까지 걸린 시간을 따로 기록합니다. 스트리밍/통화는 별도 앱의 데이터로 재현하며, 성공한 프로토콜이 있었다고 다른 앱이나 통신사에서도 된다고 일반화하지 않습니다.
